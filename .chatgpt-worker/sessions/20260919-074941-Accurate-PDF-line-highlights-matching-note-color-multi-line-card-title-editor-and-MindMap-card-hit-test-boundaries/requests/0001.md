# MarginGraph: Fix Accurate Line Highlights on PDF, Multi-line Card Title, and MindMap Hit-Testing Boundaries

Please implement the following three key fixes to achieve complete visual and functional parity with MarginNote 3:

## 1. Accurate PDF Line Highlights Matching Note Color
- **Context & Problem**:
  In MarginNote 3, for every note card that is an excerpt from a book (e.g., in `Ahrens_2017_How-to-take-smart-notes`), the PDF reader highlights the actual text lines of the excerpt on the book page.
  Currently in MarginGraph (`Sources/MarginGraphCore/PDF/PDFReaderView.swift` and `Sources/MarginGraphCore/MarginNoteImporter.swift`):
  1. Only a coarse single bounding box between `startPos` and `endPos` or a temporary jump box is rendered, which does not match the actual lines of text.
  2. The color is hardcoded to yellow rather than matching each card's `colorIndex` / theme color.
  3. Page indexing: MarginNote `ZSTARTPAGE` (and `pageNo` in `ZHIGHLIGHTS`) is 1-based (e.g., Page 53 for Ahrens), whereas PDFKit uses 0-based page indexing (`pageIndex = startPage - 1`). When jumping or displaying highlights, page 53 was looking at PDFKit index 53 (page 54), causing a 1-page offset.
- **Requirements**:
  1. For every note card that has an excerpt (`!card.highlightText.isEmpty` or has startPage/pos), highlight the actual lines on the PDF page.
  2. Support line-by-line highlight rectangles. Note: In MarginNote databases, `ZHIGHLIGHTS` is a binary plist containing `textSelLst` with an array of rect dictionaries `{"pageNo": Int, "rect": "{{x, y}, {w, h}}"}`. In addition, if line rects are not in the database or when falling back, use `highlightText` to find line selections via PDFKit (`doc.findString` / `selection.selectionsByLine()`) or calculate line rects between `startPos` and `endPos`.
  3. The highlight color of each excerpt annotation on the PDF must match that note card's color (`MarginNoteTheme.cardColors(for: card.colorIndex).accent` / NSColor) with translucent alpha (~0.35-0.45) so the underlying text remains clearly legible, matching MarginNote 3's highlighter appearance.
  4. When a card is selected or jumped to, scroll smoothly to the excerpt and emphasize the active card's highlights (e.g. selection outline or border).

## 2. Multi-line Card Title in CardEditorSheet

  - Ensure editing and saving multi-line titles preserves all newlines and persists correctly to SQLite.

## 3. MindMap Card Hit-Testing & Gesture Boundaries
- **Context & Problem**:
  In `Sources/MarginGraphCore/MindMap/TreeLayout.swift`, `TreeLayoutConfiguration` defines `nodeSize = CGSize(width: 240, height: 120)`.
  However, in `Sources/MarginGraphCore/MindMap/CardNodeView.swift`, the card view is styled with `.frame(minWidth: 220, maxWidth: 220, minHeight: 70, alignment: .topLeading)`.
  In `Sources/MarginGraphCore/MindMap/MindMapCanvasView.swift`, the card is wrapped with `.frame(width: frame.width, height: frame.height)` (240x120) with `.contentShape(Rectangle())` and `.simultaneousGesture(nodeDrag(...))`.
  This creates an invisible hit-test area (20 points to the right and up to 50 points below) where dragging near a card moves the card itself rather than panning the MindMap canvas.
- **Requirements**:
  - Align the card's interactive hit-test boundary (`contentShape` and gesture area) with the visible card boundary.
  - Sizing in `TreeLayout`, `CardNodeView`, and `MindMapCanvasView` should be consistent so that dragging on the canvas anywhere outside the visible rounded card initiates the canvas pan gesture, and only dragging inside the visible card moves/reparents the card.
